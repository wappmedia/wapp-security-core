# Native filesystem evidence helper

Version 1.1.3 adds a bounded, bootstrap-free Linux x86_64 helper for descriptor-confined filesystem inventory, selected-target rollback-byte capture, and signed explanation of a two-pass inventory mismatch.

Version 1.1.4 adds `BOUNDED_VOLATILE_RUNTIME_DISPOSITION_V1`. It requires two distinct signed drift observations with matching exact paths and behavior plus separately signed component provenance, zero IOC correlation, and no incident-persistence relation. The exact paths remain visible in the resulting inventory. Only ctime-only metadata churn or non-executable, same-inode monotonic `.log` growth can be admitted. A log under an uploads-marked surface additionally requires its separate signed component provenance and a descriptor-bound byte-exact prefix proof during capture; this is not a general uploads exclusion. Create, delete, replace, executable, unresolved, unknown-provenance, and scope-expansion cases fail closed. Raw helper output is an unverified candidate until a signed binder rederives it against the current signed disposition. The disposition and its bound inventory remain non-authorizing and never imply CLEAN, closure, remediation, prepare, READY, or apply authority.

Version 1.1.5 keeps persistent runtime identity byte-exact while treating degraded ephemeral launchers as operation-scoped lifecycles. Separate observations may use different launcher inodes only when the release launcher/helper hashes, ownership and mode metadata, operation nonce, exclusive staging, exact cleanup and signed lifecycle audits independently verify. A later volatile-inventory capture must provide its own matching lifecycle audit.

The public contract is provider-neutral. A caller supplies one absolute root; the helper rejects the filesystem root, relative paths, empty/dot components, symlink traversal, identity drift, unsupported no-atime semantics, and cap overflow. It executes only the fixed `inventory`, `rollback`, `diagnostic`, and `volatile-inventory` modes. The helper never executes WordPress, PHP, plugins, themes, or customer code, and it has no mutation or remediation authority.

`inventory` remains fail-closed on any mismatch. `diagnostic` runs the same two full descriptor-bound snapshots and is valid only when they differ. It compares their already sorted entry and unresolved-evidence streams incrementally, retaining only the two current bounded records plus the bounded emitted delta; it does not duplicate either complete snapshot and keeps the existing 256 MiB process limit. The local diagnostic parser likewise reads descriptor-bound records incrementally and writes/verifies canonical JSON without retaining the complete raw capture or materialized delta set, while preserving the same 256 MiB boundary and all existing record/byte caps. It emits a deterministic, bounded delta of normalized path identities and permitted metadata; it never suppresses the mismatch or classifies a path as benign or malicious. The local `wapp signed-drift-diagnostic` wrapper binds the raw delta to the exact operation, root, helper, Core version, snapshot hashes, runtime identity, and caller-supplied UTC observation time, then signs the canonical JSON with the existing recovery-integrity key. Every authority flag is false and `decision_eligible` is false. The artifact cannot serve as CLEAN, closure, preparation, apply, or remediation authority.

The Linux artifact is built reproducibly with exact Zig 0.15.2, stored as canonical base64 text, and bound by both encoded and decoded SHA-256 identities. The loader verifies fixed root-owned system tools, decodes into a sealed anonymous memory file, and uses `execveat`; it does not create a target-side executable. macOS is an explicit unsupported runtime for the Linux evidence operation and is used only to verify source portability and fail-closed platform behavior.

Private integrations remain responsible for site selection, transport, credentials, evidence signatures, Product/Scan lineage, customer records, and authorization. None of those are part of Public Core.
